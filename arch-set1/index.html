Q1

誤った Application Composition（アプリケーション構成）がもたらす結果について、正しく「ない」ものはどれですか？

  • Aアプリ同士が不必要に影響し合う。
  • Bアプリが独立して進化できない。
  • C上記のいずれでもない。
  • D1 つのアプリをデプロイすると、他のすべてのアプリも一緒に本番へ持っていく必要が生じることがある。

正解：C

誤った Application Composition の結果として、①アプリが独立して進化できない（ライフサイクルが異なる）、②アプリ同士が不必要に影響し合う、③1 つのアプリのデプロイに他のアプリまで巻き込まれる、のいずれも起こり得ます。したがって「正しくない」ものは存在せず、正解は「上記のいずれでもない」です。

Q2

OutSystems の Application Architecture 設計プロセスのステップを正しく表しているのはどれですか？

  • AOrganise >> Disclose >> Gather
  • BDisclose >> Organise >> Assemble
  • COrganise >> Disclose >> Assemble
  • DApplication Composition >> Organise >> Assemble

正解：B

Architecture 設計プロセスは 1. Disclose（開示）→ 2. Organise（整理）→ 3. Assemble（組み立て）の 3 ステップです。1-2-1、1-2-3-1 のように反復的に進めます。

Q3

Architecture Canvas は、_____________________ の設計をシンプルにするための OutSystems のアーキテクチャツールです。

  • AMonolithic Architecture（モノリシック）
  • BEvent-driven Architecture（イベント駆動）
  • CN-Layer Architecture（N 層）
  • DService-Oriented Architecture（サービス指向）

正解：D

Architecture Canvas は SOA（Service-Oriented Architecture）の設計を簡単にするためのツールです。再利用可能な（マイクロ）サービスの正しい抽象化と、異なる機能モジュールの正しい分離を促進します。

Q4

複数の異なるシステムからデータを収集し、収集したデータに対してビジネスロジックを実行して業務に必要なデータを生成する要件があります。最も適した統合パターンはどれですか？

  • AIntegration Service
  • BDirect Integration
  • CCold Cache Summary Data Integration + Lazy Load
  • DCold Cache Summary Data Integration + Transparency Service

正解：D

同じ種類の情報に対して複数のソース（通常は形式も API も異なる）が存在する場合、同期処理は複雑になります。このケースでは、複数ソースを統一 API で抽象化する Transparency Service と組み合わせた Cold Cache Summary Data パターンが最適です。

Q5

Discovery ツールで、各 End-user モジュールの下にモジュールがツリー状の階層を形成していることが分かりました。想定される違反はどれですか？

  • ACore 間の直接循環（Direct cycles between Cores）
  • BCore への上位参照違反（Upper violations to Cores）
  • CEnd-user への上位・横参照違反（Upper and side violations to End-users）
  • DOrchestrator への上位・横参照違反（Upper and side violations to Orchestrators）

正解：C

End-user モジュールが他の End-user モジュールから参照されると（横参照・上位参照）、各 End-user の下に健全なツリー状の階層を保てなくなります。これは「Upper and side violations to End-users」に該当します。

Q6

Assemble ステップの原則について、正しく「ない」記述はどれですか？

  • A概念的に関連するものは結合する。
  • Bライフサイクルが異なるもの、または複雑すぎるものは結合しない。
  • C既知のデザインパターンを適用する。
  • DFoundation 層の概念（統合ニーズ・NFR）、Core ビジネス層の概念、End-user の概念を特定する。

正解：D

Assemble の原則は、①概念的に関連するものは結合する、②ライフサイクルが異なる／複雑すぎるものは結合しない、③既知のデザインパターンを適用する、④再利用ロジックを統合ロジックから分離する、です。「概念を特定する」のは Disclose ステップの活動です。

Q7

命名規則の採用は Application Architecture 設計に利点をもたらします。次のうち、命名規則を採用する利点で「ない」ものはどれですか？

  • Aリファレンスアーキテクチャを強制する。
  • Bパターンを標準化する。
  • Cエラーコードを回避する。
  • D各モジュールの性質を明らかにする。

正解：C

命名規則は各モジュールの目的を理解しやすくし、リファレンスアーキテクチャの強制やパターンの標準化に役立ちます。エラーコードの回避は命名規則の効果ではありません（例外処理の話です）。

Q8

良いアーキテクチャの利点として正しいものはどれですか？

  • A管理不能な依存関係
  • B複雑さを管理できる
  • C貧弱なサービス抽象化
  • D動きの遅いレガシーシステム

正解：B

良いアーキテクチャは複雑さ（complexity）を管理可能にします。他の選択肢はいずれも、アーキテクチャが悪い場合に起こる問題です。

Q9

Architecture 設計プロセスには 3 つのステップがあります。そのステップで「ない」ものはどれですか？

  • AOrganise（整理）
  • BDisclose（開示）
  • CAssemble（組み立て）
  • DPlan（計画）

正解：D

3 ステップは 1. Disclose、2. Organise、3. Assemble です。Plan は含まれません。これらは 1-2-1、1-2-3-1 のように反復的に実施します。

Q10

Architecture 設計プロセスにおいて、Disclose ステップの活動として「有効でない」ものはどれですか？

  • A情報アーキテクチャを定義する。
  • B既知のデザインパターンを適用する。
  • C統合技術を定義する。
  • Dユーザーストーリー、ペルソナ、ロールを定義する。

正解：B

「既知のデザインパターンを適用する」は Assemble ステップの活動です。Disclose ステップでは、ユーザーストーリー／ペルソナ／ロール、情報アーキテクチャ、統合ニーズと技術などを明らかにします。

Q11

Calculation Engine（_Eng）モジュールを作成する正当な理由はどれですか？

  • A複雑な計算（例：複利計算、工学的な荷重圧力計算）をサポートするため。
  • B複数のビジネスロジックモジュールに実装された異なる複雑なロジックを抽象化するため。
  • CCore Widget モジュールから再利用可能なアクションを提供するため。
  • DEntity と CRUD 編集を持つ概念をサポートするため。

正解：A

_Eng（Calculation Engine）は、保険シミュレータのような複雑な計算ロジックを分離するためのモジュールです。Entity+CRUD は _CS、再利用 UI は _CW の役割です。

Q12

Cold Cache Summary Data 統合パターンのバリエーションで「ない」ものはどれですか？

  • ABatch Sync
  • BReal-Time Sync
  • CQueued Real-Time Sync
  • DDirect Sync

正解：D

Cold Cache Summary Data のバリエーションは Batch Sync / Real-Time Sync / Queued Real-Time Sync / Ordered Real-Time Sync です。「Direct Sync」というものは存在しません。Direct Integration は Cold Cache とは別の統合パターンで、_IS 経由で外部システムから直接データを取得し、_CS に外部データを保持する Entity を持ちません。

Q13

Assemble の原則（推奨パターンに合致するもの）はどれですか？

  • Aライフサイクルが異なる概念は分けておく。
  • Bビジネス概念と統合ニーズを開示する。
  • Cすべての統合を 1 つのモジュールにまとめる。
  • Dすべてのビジネス概念を分離する。

正解：A

Assemble の原則は「概念的に関連するものは結合する」「ライフサイクルが異なる／複雑すぎるものは結合しない」「既知のデザインパターンを適用する」「再利用ロジックを統合ロジックから分離する」です。「開示する」は Disclose ステップ、残り 2 つは原則に反します。

Q14

次のうち、正しく「ない」記述はどれですか？

  • AClone a Built-in Style Guide では、Base Theme の新バージョンの恩恵を受けられる。
  • BCustom Template は Base Template からクローンされる。
  • CClone a Built-in Style Guide の利点は、余分な間接参照を避けることで得られる最高のパフォーマンスである。
  • DBase Theme と Base Template は OutSystems UI または他の Theme のいずれでもよい。

正解：A

Clone a Built-in Style Guide（既存 Theme に大幅な変更を加える場合に使用）では、Custom Theme が Base Theme をクローンします。利点は間接参照がなくパフォーマンスが最良であること、課題は Base Theme の新バージョンの恩恵を受けられないことです。

Q15

Architecture Canvas を採用する利点を述べているのはどれですか？

  • ACanvas はアーキテクチャ原則に従い、修正する自動的な方法を提供する。
  • BCanvas は検証不要で、より速いアーキテクチャ設計を提供する。
  • CCanvas はビジネスユーザーの協力と理解を容易に促進する方法を提供する。
  • DCanvas は検証ツールに支えられた、アーキテクチャ設計への体系的なアプローチを提供する。

正解：D

Architecture Canvas は、検証ツール（Discovery / AI Mentor Studio）に支えられた体系的な設計アプローチを提供します。自動修正や検証不要というものではありません。

Q16

Foundation 層について、正しく「ない」記述はどれですか？

  • A再利用性の低い要素が Foundation 層に定義される。
  • BFoundation 層では、外部ユーザー向けに Core Widget を定義できる。
  • CFoundation 層モジュールの典型的な要素は Data、Logic、Interface、Process である。
  • DFoundation 層モジュールの典型的な要素は Data、Logic、Interface である。

正解：C

Foundation 層には再利用性の高い要素が定義され、典型的な要素は Data（入出力 Structure、非コア Entity）、Logic（正規化 API、例外処理、SSO／セッション、共通ロール）、Interface（UI パターン、Theme／Layout／例外フロー）です。Process（BPT）は Core 層の要素で、Foundation には含まれません。※選択肢 A「再利用性の低い要素」も公式には誤り（Foundation は再利用性の高い要素）で、本問は不正確な選択肢が 2 つある設問です。出題の想定正解は C です。

Q17

End-user モジュール 1 つ、Service モジュール 3 つ、Library モジュール 2 つで構成されるアプリケーションの種類は何ですか？

  • ACore Service Application
  • BEnd-user Application
  • CLibrary Application
  • D上記のいずれでもない

正解：B

End-user モジュールを 1 つでも含むアプリケーションは End-user Application に分類されます。Service モジュールと Library モジュールはそれをサポートする役割です。

Q18

OutSystems のアーキテクチャを検証するために使うツールはどれですか？

  • AAI Mentor Studio
  • BService Center
  • CDiscovery
  • DIntegration Studio

正解：C

Discovery は、アーキテクチャを分析・計測し、改善方法を理解するためのビジュアルツール（Forge コンポーネント）です。モジュール依存関係、アーキテクチャルール違反、各モジュール／アプリの要素数などを表示します。公式ドキュメント（Domain Driven Design ページ）でも「アーキテクチャを検証するには Forge の Discovery を使う」と記載があります。なお現在は AI Mentor Studio（旧 Architecture Dashboard）でも検証できるため、実務上は両方が正解になり得ます。

Q19

OutSystems において、Core Application に含めることができるのは？

  • AFoundation モジュールと Core モジュール
  • BEnd-user モジュールと Core モジュール
  • CFoundation モジュールのみ
  • DEnd-user、Core、Foundation モジュール

正解：A

Core Application に含められるのは Foundation モジュールと Core モジュールのみです。End-user モジュールを含めると End-user Application になります。

Q20

Application Architecture を定義するには概念の適切な粒度が重要です。粒度を左右する正しい基準はどれですか？

  • AUser Process、Complexity、Service isolation
  • BComplexity、Independent life cycles
  • CComplexity、Independent life cycles、Service isolation
  • DIndependent life cycles、Service isolation

正解：C

粒度を決める基準は Complexity（複雑さ）、Independent life cycles（独立したライフサイクル）、Service isolation（サービスの分離）の 3 つです。

Q21

メニューやログインなどの要素は異なるアプリ間で共有できます。あるユースケースでは、メニューとログインの両方が Theme の中に定義されます。それはどのユースケースですか？

  • AIntranet
  • BPortal
  • C上記のいずれでもない
  • DIndependent Apps

正解：B

すべてのアプリがメニューとログインフローを参照します。それらをどこに定義するかは Style Guide の目的次第で、Theme の中に置くと複数アプリで再利用できます。これは Portal ユースケースです。

Q22

Specialize a Built-in Style Guide の最適なユースケースはどれですか？

  • A既存 Theme に「大幅でない」変更を加える場合
  • B上記のいずれでもない
  • C既存 Theme に大幅な変更を加える場合
  • Dカスタム Style Guide が既存 Theme の恩恵をまったく受けられない場合

正解：A

Specialize a Built-in Style Guide は既存 Theme への小さな変更向けです。Custom Theme が Base Theme を参照するため、Base Theme の新しい変更を継承し続けられる一方、CSS 等の追加インポートによりパフォーマンスは劣ります。大幅な変更なら Clone を選びます。

Q23

明確に定義された Application Architecture の利点で「ない」ものはどれですか？

  • A計画を支援する
  • B貧弱なサービス抽象化
  • Cリスクを低減する
  • Dコストを削減する

正解：B

良いアーキテクチャは計画の支援、リスク低減、コスト削減をもたらします。「貧弱なサービス抽象化」は利点ではなく、悪いアーキテクチャの症状です。

Q24

アプリケーションで命名規則を採用することがなぜ重要なのですか？

  • Aリファレンスアーキテクチャを強制するため。
  • Bパターンを標準化するため。
  • C残りの選択肢はすべて正しい！
  • D各モジュールの性質を明らかにするため。

正解：C

命名規則の目的は、①各モジュールの性質を明らかにする、②リファレンスアーキテクチャを強制する、③パターンを標準化する、の 3 つです。したがって「残りの選択肢はすべて正しい」が正解です。

Q25

次のうち、有効な統合パターンで「ない」ものはどれですか？

  • ACold Cache Summary Data
  • BDirect Integration
  • CExternal Core Service Pattern
  • D3 Layer Pattern

正解：D

統合パターンは ①Direct Integration（別名 External Core Service Pattern）と ②Cold Cache Summary Data（Batch / Real-Time / Queued / Ordered Sync）です。「3 Layer Pattern」は統合パターンではありません。Direct Integration は常に最新データが得られる反面、外部システムへの負荷・遅延・Aggregate を活用できない・_IS 拡張の依存といった制約があります。

Q26

Architecture Canvas は多層フレームワークです。このフレームワークを使う利点で「ない」ものはどれですか？

  • Aパフォーマンスのボトルネックの候補を特定する。
  • B変更の影響を最小化する。
  • Cライフサイクルの独立性を最適化する。
  • D再利用可能なサービスの正しい抽象化を促進する。

正解：A

Architecture Canvas は実装の詳細には踏み込みません。パフォーマンス面で注意が必要なコンポーネントに気付くきっかけにはなり得ますが、それはアーキテクチャ設計そのものの範囲ではありません。

Q27

OutSystems では、無関係な概念を同じモジュールにまとめることは推奨されますか？

  • Aはい。循環参照を避け、生成コードのフットプリントを減らせるため。
  • Bいいえ。両方の概念を必要とするコンシューマに不要な複雑さを加えるため。
  • Cはい。参照数が減り、デプロイが簡単になるため。
  • Dいいえ。概念のライフサイクルの独立性を妨げ、コンシューマに不要な影響を与えるため。

正解：D

無関係な概念を 1 つのモジュールにまとめると、それぞれのライフサイクルの独立性が失われ、片方だけを使うコンシューマにも不要な影響が及びます。

Q28

正しい Application Composition のルールで「ない」ものはどれですか？

  • Aアプリケーションを正しくレイヤー分けする
  • BEnd-user または Orchestration 間で横参照しない
  • Cモジュールを正しくレイヤー分けする
  • D異なるオーナーを混在させない

正解：B

Application Composition の 4 ルールは、①モジュールを正しくレイヤー分けする、②アプリケーションを正しくレイヤー分けする、③異なるオーナーを混在させない、④異なるスポンサーを混在させない、です。「End-user 間の横参照禁止」はモジュール検証ルールであり、Application Composition のルールではありません。

Q29

Integration Service は統合の複雑さを隠蔽し、再利用しやすいサービスとして抽象化します。Integration Wrapper Canvas の関心事で「ない」ものはどれですか？

  • A出力の正規化（Normalize Outputs）
  • B外部 API の呼び出しと監査（Call and Audit the external API）
  • C上記のいずれでもない
  • D認証ロジック（Authentication Logic）

正解：C

Integration Wrapper Canvas のステップは、検証／セキュリティロジック → 認証ロジック → 入力マッピング → 外部 API 呼び出しと監査 → エラー処理の正規化 → 出力の正規化 →（必要なら）例外処理、です。選択肢はすべて関心事に含まれるため「上記のいずれでもない」が正解です。

Q30

Customer Management のユーザープロセスには、顧客ダッシュボード、顧客メッセージング、サービスリクエスト、顧客トランザクションなど、複数のサブプロセスがあります。この要件でモジュールを設計・定義する際、粒度を適切にするためにどの基準を選びますか？

  • ACanvas
  • BComplexity（複雑さ）
  • CService isolation（サービスの分離）
  • DIndependent life cycles（独立したライフサイクル）

正解：B

1 つの概念が大きすぎて単一モジュールに収まらない場合、各モジュールの複雑さを管理可能に保つために複数モジュールへ分割します。これは「Complexity」基準に基づく分割です。

Q31

Application Architecture の粒度を正しく定義するのに影響するのはどれですか？

  • AIndependent life cycles、Define Modules、No Upward References
  • BComplexity、Service isolation
  • CComplexity、Independent life cycles、Service isolation
  • D機能要件、非機能要件、統合ニーズ

正解：C

粒度は ①Complexity（大きすぎる概念は分割）、②Independent life cycles（独立して管理・並行開発・異なる進化速度）、③Service isolation（統合パターンに応じた技術コンポーネントの分割）の 3 基準で決まります。

Q32

Cold Cache Summary Data 統合パターン（Batch Sync）の「欠点」とされるものはどれですか？

  • Aデータが古くなる可能性がある。
  • Bアプリケーションの遅延が増える。
  • C外部システムへのアクセスが増える。
  • Dデータが常に最新である。

正解：A

Batch Sync の利点はシンプルな API、OutSystems 内でのデータマッシュアップ、ソースシステムへの影響が少ない、同期がコンシューマに影響しないこと。欠点は、次の同期までデータが古くなる可能性があることです。遅延増加やアクセス増加は Direct Integration の欠点です。

Q33

Application Composition の検証ルールについて、正しい記述はどれですか？

  • A共通モジュールやサービスは、他のアプリから参照できる別アプリに分離すべきである。
  • BFoundation 層のアプリケーションは End-user 層のアプリケーションを参照できる。
  • Cアプリのオーナーは混在させるべきでないが、スポンサーの混在はリリースに直接影響しない。
  • Dモジュール検証ルールをすべて守れば、Application Composition は健全で保守・デプロイが容易になる。

正解：A

再利用性が鍵であり、共通モジュール／サービスを別アプリに分離することで参照の問題を避けられます。Foundation は End-user を参照できず、スポンサー混在も避けるべきで、モジュールルールだけではアプリ構成の健全性は保証されません。

Q34

Foundation モジュールで使用「できない」命名規則はどれですか？

  • A_Lib
  • B_API
  • C_IS
  • D_Th

正解：B

Q37

OutSystems アプリで、外部 System of Records のサマリーデータを表示する必要があり、そのデータは変更・更新されることがなく、外部システムからの取得コストが高い場合、最適な統合パターンはどれですか？

  • BCold Cache Summary Data + Queued Real-Time Sync
  • CCold Cache + Batch Sync
  • DCold Cache Summary Data + Real-Time Sync
